# Build Instructions for Quant Analysis Assistant using PyInstaller

This document outlines the steps and considerations for packaging the "Quant Analysis Assistant"
Python application into a standalone executable using PyInstaller.

## 1. Install PyInstaller
If you haven't already, install PyInstaller using pip:
```bash
pip install pyinstaller
```

## 2. Recommended PyInstaller Command
The following command is a good starting point. You'll likely run this from the root directory of your project (e.g., `/app`).

```bash
pyinstaller --name "QuantAnalysisAssistant" \
            --windowed \
            --noconfirm \
            main_gui.py \
            --add-data "data_manager.py:." \
            --add-data "strategy_configurator.py:." \
            --add-data "backtesting_engine.py:." \
            --add-data "simulated_trading.py:." \
            --add-data "reporting.py:." \
            --add-data "gui_strategy_config_tab.py:." \
            --add-data "gui_data_management_tab.py:." \
            --add-data "gui_backtesting_tab.py:." \
            --add-data "gui_simulation_tab.py:." \
            --add-data "gui_report_viewer_tab.py:." \
            # Add other non-Python files or directories if needed (e.g., icons, initial configs)
            # --icon="path/to/your/app_icon.ico"  # For Windows
            # --icon="path/to/your/app_icon.icns" # For macOS
```

**Explanation of Command Options:**

*   `--name "QuantAnalysisAssistant"`: Sets the name of the executable and the output folder.
*   `--windowed`: Prevents a command-line console window from appearing when the GUI application is run. Essential for PySide6 GUI apps.
*   `--noconfirm`: Overwrites the output directory without asking for confirmation. Useful for build scripts.
*   `main_gui.py`: This is your main application script that launches the GUI.
*   `--add-data "<source_file_or_dir>:<destination_in_bundle>"`:
    *   This is crucial for including your other Python modules (`.py` files) that are part of the application but not automatically discovered as top-level imports by PyInstaller if they are dynamically imported or live in the same directory as `main_gui.py` without being explicit package structures.
    *   Using `.` as the destination means these files will be placed in the root of the bundled application structure, allowing your existing imports (`from data_manager import ...`, `import strategy_configurator`, etc.) to work as they do during development.
    *   If you had actual data files (like initial strategy templates in `strategies/` or example data in `data/`) that you wanted to bundle with the application *read-only*, you would use `--add-data "strategies:strategies"` or `--add-data "data:data"`.

**One-File vs. Directory-Based Build:**

*   **Directory-Based (default, as above)**: Creates a folder containing the executable and all its dependencies. This is generally recommended for easier debugging and managing associated files.
*   **One-File (`--onefile`)**: Bundles everything into a single executable file.
    *   **Pros**: Simpler distribution as a single file.
    *   **Cons**: Slower startup time (as it needs to extract files to a temporary location at runtime), can be harder to debug, and might have issues with certain types of bundled files or paths.
    *   If using `--onefile`, paths to bundled resources (accessed via `sys._MEIPASS`) need careful handling. Our current approach of creating data directories at runtime is generally more compatible with `--onefile` if those directories are for user-generated content.

    To use one-file mode, add `--onefile` to the command:
    ```bash
    pyinstaller --name "QuantAnalysisAssistant" --windowed --onefile --noconfirm main_gui.py --add-data ...
    ```

## 3. Handling Data Directories (`data/`, `strategies/`, `reports/`)

Our application currently creates these directories at runtime if they don't exist (e.g., `data_manager.py` ensures `data/` exists, `reporting.py` ensures `reports/` exists). This is a good approach for user-generated content.

*   **Runtime Creation (Current Approach)**:
    *   **Pros**:
        *   The application starts clean.
        *   User data is stored in a predictable location relative to the executable (if directory build) or in a standard user data path (if more advanced path logic is added).
        *   Works well with both one-file and directory builds.
    *   **Cons**: Initial bundled example files are not included unless explicitly added with `--add-data`.
    *   Our current code (e.g., `os.makedirs(DATA_DIR_GUI, exist_ok=True)`) handles this. The `STRATEGIES_DIR`, `DATA_DIR_GUI`, `REPORTS_DIR_GUI` constants defined relative to the script locations will generally work well, especially in a directory-based build. For one-file builds, these will resolve to paths inside the temporary extraction folder (`sys._MEIPASS`), which is usually fine for reading bundled files, but user-writable data should ideally go to user-specific directories (e.g., AppData, Application Support). Our current approach of creating them in the CWD (if not bundled) or next to the executable is simpler but might have permission issues in restricted environments (like `C:\Program Files`).
    *   **Recommendation**: For user-generated data, continue creating these directories at runtime. For a more robust solution with `--onefile` or for installations in protected locations, consider using `appdirs` or `QStandardPaths` to find appropriate user-writable locations.

*   **Bundling Initial/Example Data (Optional)**:
    *   If you have default strategy templates, example data files, or initial reports you want to ship with the application, you can bundle them using `--add-data`.
    *   Example: To bundle an `example_strategy.json` into the `strategies` folder within the app bundle:
        ```bash
        --add-data "path/to/your/example_strategy.json:strategies"
        ```
    *   Your application would then need to be aware that these bundled files are read-only and should be copied to a user-writable location if they need modification. The current code in `strategy_configurator.py` saves new strategies to `strategies/` which would be user-writable if created at runtime next to the executable.

## 4. Potential Issues and Solutions

*   **Hidden Imports (`--hidden-import`)**:
    *   PyInstaller might not always detect all necessary imports, especially for libraries that use dynamic imports or plugins (e.g., some pandas or numpy components, or specific `PySide6` modules if not explicitly imported).
    *   If you get `ModuleNotFoundError` at runtime from the bundled app, identify the missing module and add it using `--hidden-import=modulename`.
    *   Example:
        ```bash
        --hidden-import="pandas.plotting"
        --hidden-import="PySide6.QtSvg"
        ```
    *   Commonly needed for `pandas`, `numpy`, `matplotlib` backends, and specific `PySide6` XML/SVG/SQL modules if used.

*   **PySide6 and Qt Plugins**:
    *   PySide6 applications often rely on Qt platform plugins (e.g., for window styling, image formats). PyInstaller usually handles these, but if you encounter issues (like missing styles or images not loading), you might need to ensure the `PySide6/plugins/platforms` (and other plugin directories) are correctly bundled or accessible.
    *   The `--add-binary` option can be used for more complex binary file inclusions if needed.

*   **Application Icon**:
    *   Use the `--icon` option to specify an application icon:
        *   For Windows: `--icon="path/to/your/app_icon.ico"`
        *   For macOS: `--icon="path/to/your/app_icon.icns"`
        *   For Linux: Often handled by the desktop environment, but you can specify a `.png` for some builders.

## 5. Building the Application
1.  Navigate to your project's root directory in the terminal.
2.  Run the PyInstaller command (chosen from section 2).
3.  PyInstaller will create a `build/` folder (temporary build files) and a `dist/` folder (containing the packaged application).
4.  The application will be in `dist/QuantAnalysisAssistant/` (for directory build) or `dist/QuantAnalysisAssistant.exe` (for one-file build on Windows).

## 6. Testing the Executable
*   Navigate to the `dist/QuantAnalysisAssistant/` directory.
*   Run the executable (`QuantAnalysisAssistant.exe` on Windows, `QuantAnalysisAssistant` on macOS/Linux).
*   Test all functionalities:
    *   Tab switching.
    *   Strategy configuration saving/loading.
    *   Data management: listing, importing, downloading, previewing, preprocessing.
    *   Backtesting: running backtests, viewing stats and equity curves.
    *   Simulation: running simulations, viewing stats and plots.
    *   Report Viewer: listing and viewing generated reports and plots.
*   Check for any console errors if you run it from a terminal (or if you built without `--windowed` for debugging).
*   Verify that the `data/`, `strategies/`, and `reports/` directories are created and used correctly (e.g., in the same directory as the executable or in the user's home directory if you modify path logic).

## 7. Final Considerations
*   **Dependencies**: Ensure all Python dependencies (`pandas`, `numpy`, `yfinance`, `python-binance`, `openpyxl`, `backtrader`, `PySide6`, `matplotlib`) are correctly included by PyInstaller. Usually, direct imports are found, but check the build warnings.
*   **Cross-Platform Builds**: PyInstaller builds for the platform it's run on. To create a Windows executable, run PyInstaller on Windows. For macOS, run on macOS.
*   **Virtual Environments**: It's highly recommended to use a virtual environment for your project to manage dependencies. Build your PyInstaller executable from within this activated virtual environment.

This guide should provide a comprehensive starting point for packaging your application. You may need to iterate on the PyInstaller command and options based on any issues encountered during testing.
